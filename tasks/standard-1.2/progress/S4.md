## Deviations

- Workflow fixtures with warnings follow the repository's naming
  (`pass_<name>_warn`), not the design's `warn_<name>`:
  `pass_grounding_key_in_1_1_warn`, `pass_audit_retention_warn`.
- `tests/fixtures/pass_audit_require_record.workflow_catalog.yaml` (S2b's)
  bound `retention: P1Y`, which is outside the §5.10.1 grammar and now
  W614; it binds `P365D` instead (the migration of repository content a new
  warning hits, design part 8).
- W616 (§11.5): besides the design's §2.20 text for S6, the validator's
  `FEATURES` table gains two 1.2 entries (`grounding@1` with its field, and
  F505 in `on_error`), so a 1.1 workflow that uses them gets W616 like the
  other 1.2 features; `recovery.rs`'s test expects W616 for F505 in its 1.1
  catalog.
- The grounding vectors pin `counted` and `legacy` for grounded and
  inferred outputs only: the check stops at the first F505, so the counts
  of a refused output are not part of the rule. `_core.check_grounding`
  reports 0 for them.
- `GroundingPolicy.require` takes the `require` list of 1.1 producers as a
  frozenset (design), so a repeated id is not refused in Python as it is by
  the core's `Policy::new`; the core refuses it when the runner passes the
  policy on (S303-shaped `ValueError`).
- `COORDINATION_REF_PREFIXES` is defined in
  `grounded_agency/state/evidence_store.py` (the store answers legacy-kind
  queries with it) and imported by `coordination/_evidence_helpers.py`,
  which refuses any other prefix: one place, and no import cycle (the
  design put it in `_evidence_helpers.py`).
- The runner reads what a submit added with `run.trace(since=run.trace_seq)`:
  `_core.Run.trace_seq` (the `seq` the next trace event gets) is a small
  getter added beside `trace(since)`, since a runner that has taken the
  trace cannot count it.
- §5.18.10's `persist` and `audit` secret rows are applied by the SDK
  adapter (PreToolUse, F504) and the binding (`groundedTool`, F504) with a
  credential-shape check, `Redactor.holds_credential` / `holdsCredential`
  (registered values, key and token formats, and assignments whose value
  is quoted 8+ without whitespace or unquoted 12+ mixing letters and
  digits), the same rule as the plugin's `hooks/secret_scan.sh`, not the
  redactor's broader assignment rule: a refusal of prose such as
  `token: rotate monthly` would block ordinary memory. Both statements drop
  the `persist`/`audit` line and the redaction line (the adapter redacts
  its call records and refusal messages; the binding redacts every trace
  entry it writes).
- Under a grounding policy, the SDK adapter checks a call's output where it
  has one: the guarded MCP tools of `create_grounded_mcp_server` (their
  `structuredContent`, else the §5.18.9 text). A result with no capability
  output is refused with F505 there. Claude Code's own tools return no
  capability output, so no policy applies to them (the adapter's
  output-contract row stays in its statement).
- The binding's `src/package.ts` is the packed agent's entry point
  (`PackedExports`: agents, tools, hooks, endpoints), not a library index;
  the evidence module is imported from `src/acs/evidence.ts` as the other
  binding modules are, so nothing is added there.
- The `persist` and `audit` command hooks read the tool call once with
  `INPUT="$(jq -c . 2>/dev/null)"`, not the design's `INPUT="$(cat)"`: a hook
  that cannot find `cat` (the test that empties `PATH` to remove `jq`) would
  otherwise fail before saying jq is missing. Their refusals open with the
  Standard's code and name (`F504 CONSTRAINT_VIOLATED:` for a path or a
  credential, `R407 SAFETY_CHECK_FAILED:` for a call they cannot read), as
  S1's rollback and send hooks do.
- Skill anchor examples: refs keep their text, with `file:` added to a bare
  path; kinds follow the scheme, `x-doc` (a vendor kind) for documentation
  references with no medium of §6.5 (`doc:`, `fowler:`, `zod:docs:` ...),
  `human_note` for what a person wrote (`issue:`, an inquiry's `input:`),
  and `record` for the agent system's own values (`policy:`, `plan:`,
  `task:` ...). The `invoke` skill's nested outputs gain anchors, and its
  composed `evidence_anchors` a comment on §5.20.
- The binding's output check is `encodeCapabilityOutput` (acs-core), which
  replaced 1.1's `outputProblems`; it is unchanged, and the grounding check
  runs after it only under the `grounding` option.
- Figure gap (site rule, 1800px on enforced pages), met with restructured
  text and real figures, no new exemption:

    full, and the design's longer §3.1 made its principles run 2653px.
