## Deviations

- **`AcsCore.context(init)` takes the documents; `loadDocuments()` reads the
  bundled `documents.json`.** The design's `context(init?)` defaulted to the
  bundle synchronously, which cannot read a file or fetch a URL; the bundle
  is loaded asynchronously by `loadDocuments()` and passed in.
- **WebAssembly profile refusals use kind `bad_request` with diagnostics**
  (the design's kind list has no profile kind).
- **`core/src/refs.rs`**: an index is parsed as `u64` and held saturated as
  `usize`, so `${a[18446744073709551615]}` is a missing index on a 32-bit
  target too (the expression fixture `index-huge` failed through
  WebAssembly). Shared file, local change; no result changes on 64-bit.
- **`npm publish --ignore-scripts`** in the publish job: the module is built
  and tested in the step before, and `prepack` would rebuild it.
- **Package tests need the built module.** `npm test` reads
  `dist/acs_core.wasm`; CI runs `build:wasm` and `build` before `check` and
  `test`, and CLAUDE.md/AGENTS.md list that order. The binding job builds
  only `build:ts` (it uses the plain entry; `build` now bundles documents
  through the module).
- **`GroundedAgentConfig(profiles=…)` requires `approval="ask"`**: with
  approvals off, the approvals a profile requires would be skipped silently.
- **`tools/validate_profiles.py`** accepts a file named after the domain
  with `-` or `_` (the scaffold writes `<name>.yaml` for a kebab name).
- **The adapter keeps `UNCLASSIFIED_TOOL` unchanged under profiles**: it
  already needs a checkpoint and approval (a person's, in this adapter), and
  its identity marks an unbound tool for the evidence collector.
- **Plugin and package versions are not bumped** (maintainer: versions change
  only at a release); the CHANGELOG and CLAUDE.md record that the release
  carrying the skill renames is a plugin MAJOR (3.0.0).
- **§1 item numbering**: the profiles item is 11 on this branch; S2b's host
  protocol item goes before it at merge (D2: S2b 11, S6 12).
- **Figure gap (check-runs) met with figures drawn from the text, and
  tighter wording.** The design's text left runs over 1800px on the current
  Standard and `/domains/`. Without a new exemption:
  - tables with a Code column, drawn as diagnostic tiles
    (`CODE_TABLE_FIGURES`, which now takes the table's `index`): §4.1.2's
    dialect forms (with a Rendering column in place of the rendering
    paragraph's list), §5.21.2's diagnostics (in place of the bullets),
    §5.21.3's raises (a Code column) and other rules (in place of the
    "also puts in force" bullets; the minimum confidence paragraph follows),
    §11.5's and §11.6's codes (in place of the sentences and bullets);
  - field tables drawn as a Port column (`TABLE_FIGURES`): §5.21.2's members
    (`Field | Type | Required | Description`, one row per informative member)
    and §7.1's id parts (in place of the grammar fence and bullets; the
    examples fence stays last, which `tests/test_entities.py` reads);
  - the `decay` figure moves from §8.1's heading to the end of §8.1, and
    `suite` from §10.3's heading to after its fixture list;
  - §10.2's profiles paragraph is folded into §10.3's vectors paragraph; §1
    item 11, the §2 rows, §5.1's `profile` row, §8.2/§8.3, §10.3 and §11.5
    are worded more tightly; `docs/domains/README.md`'s Status section
    replaces its member table with a paragraph (§5.21 has the table).
