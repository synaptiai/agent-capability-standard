## Deviations

- **Test files.** The Python tests the design adds to `tests/test_runner.py`
  (S2b's) and `tests/test_checkpoint_persistence.py` (S1's) are in files of
  their own, named after S5's features (FOUNDATION F4: a stream's tests
  named after its features are its own): `tests/test_runner_effects.py`
  (the host's defaults, destinations through the runner, durable keys, the
  `run` scope) and `tests/test_snapshots.py` (the tracker with snapshots,
  pruning). The adapter tests are `tests/test_adapter_effects.py`. The
  Rust executor tests are `core/tests/effects.rs`.
- **A secret in memory is refused by the narrow rule.** `MemoryStore`
  refuses data or a key that `Redactor.holds_credential` recognises (S4's
  refusal rule, FOUNDATION-notes S4), not everything `redact` would
  change; the message names the JSON pointers `redact` finds.
- **Snapshot directories excluded whole.** A directory `exclude` names as
  `<dir>/**` without a wildcard (`.git/**`, `.ssh/**`) is not walked and is
  listed once in `excluded` as `<dir>/`, like the never-within-reach
  directories; `SECRET_PATHS` also lists the top-level forms (`.ssh/**`,
  `id_ed25519*`) that `fnmatch`'s `**/x` does not match.
- **Key fill on restore.** A pending `InvokeCapability` without a key gets
  `<run_id>:<id>` whatever the state's version (the design says version 1):
  a version-2 state saved before this change has none either.
- **§2 rows stay in the first table.** S3's note puts S5's four rows in
  the third table (tool-calling hosts, catalogs and delegation); they stay
  in the first, right after S2b's run terms, as FOUNDATION D2 orders them
  (S2b's five, then S5's four): **Pass** and **Idempotency key** are run
  terms. The site reads run terms from every table.
- **Figure-gap after the merge.** S3's, S4's, S5's and S6's §10.3 vector
  paragraphs made a 1877px run, and S3's and S5's §3.3 bullets made the
  home page's design principles 1815px. §10.3 gained a figure of its own,
  `effect-vectors` ("The destination and memory vectors", counted from the
  two files; Astro, Markdown twin and slot), and S5's §3.3 bullet is
  shorter (it no longer restates what a rollback returns, which §4.4.1
  says, nor names `constrain`, which the W601 bullet does).

## Review round 1

Nine issues on S5's commits since `round3/S5-base`, the merge after
`round3/S5sync-base` and its wiring. Each was verified; all nine were real
and are fixed at the root, each with a test that fails without the fix.

1. [x] **Stale "refused until the destination check lands" texts**
   (medium). Real: both lines predate S5 and S5's rewording missed them.
   `packages/acs-core/README.md` now says the executor puts a profile's
   `allowed_destinations` in force beside the `destinations` start option
   (F504 `destination_not_allowed` before approval; a restored run keeps
   its policies), its module table has `destinations` and `duration` rows,
   and its vector list names `destinations/match.json`. The annex IV risk
   row says the policy is in force (executor, adapter, binding; F504
   before approval). A grep for the stale phrases finds nothing else
   (RFC-0010's line is its general rule for an unenforced rule).
2. [x] **`RolledBack` with `not_covered: null` accepted** (low). Real:
   serde read `null` as `None`. `Response::RolledBack.not_covered` now
   deserialises through `present_list` (`core/src/exec/mod.rs`), so a
   member that is present and not a list, `null` included, is a malformed
   response (Python `ValueError`, WebAssembly `bad_request`); absent is
   still `None`. Tests: `core/tests/effects.rs::rolled_back_bad_reason_refused`
   (null, object, string), `tests/test_runner_effects.py::test_a_malformed_not_covered_is_refused`
   (the issue's repro through `_core`).
3. [x] **`memoryTools` states no durability or entry limit** (low). Real.
   The binding README, `docs/integrations/standard_agents.md` and the
   header of `src/acs/memory.ts` state, for scope `session`: entries
   survive a restart (the Standard Agents runtime MUST keep thread values
   across restarts and redeploys), are kept while the thread lasts unless
   `ttl` ends them, `max_value_bytes` per value (1,000,000 by default), and
   no limit of the binding's on their number (the runtime's own caps, which
   it MAY set, apply). ACS-48's resolution cites the statements.
4. [x] **`IdempotencyLog`: a torn last line swallows the next entry**
   (high). Real: reproduced (two transmissions under one key). `_load`
   now cuts a torn last line off the file (`_repair`, at the offset where
   that line starts) and ends a whole last entry whose newline was not
   written, so every later append is a line of its own. Tests:
   `test_an_entry_after_a_torn_line_survives_a_restart` (the issue's
   repro: `outcome_unknown`, one transmission),
   `test_more_entries_after_a_torn_line_load`,
   `test_a_whole_last_entry_without_its_newline_is_kept`.
5. [x] **The memory scope check fails valid 1.1 workflows** (medium).
   Real: the maintainer's backward-compatibility rule wins over the
   design. The check in `Machine::output()` now applies only when the
   frame's workflow `targets_1_2`; below 1.2, `scope` is W616 and passed on
   unchecked. §4.5 and §5.19.7 say so; RFC-0009 (§8, Backward
   compatibility, Conformance test updates), the running-workflows guide,
   the persist and recall skills, ACS-27's resolution and the CHANGELOG
   line follow. New runtime fixture `persist_scope_v11_unchecked` (header
   1.1.0, an output without `scope` completes); 350 fixtures.
6. [x] **Adapter: a composite that invokes a send passes the destination
   policy** (medium). Real. While a policy is in force,
   `GroundedAgentAdapter._destination_refusal` refuses (F504) a call whose
   mapping's `invokes` reach, transitively, a binding that performs
   `send` (`ToolCapabilityMapper.invoked_senders`): the adapter does not
   see nested calls, so it cannot tell where they go. The adapter's
   conformance statement names this in `host_gaps`; the SDK guide, ACS-52's
   resolution and the CHANGELOG say so. Test:
   `tests/test_adapter_effects.py::test_a_composite_that_invokes_a_send_is_f504_under_a_policy`
   (direct and two levels deep; no policy, no check).
7. [x] **A rollback's `not_covered` omits sends whose outcome is unknown**
   (medium). Real. `IdempotencyLog.performed_since` returns `started`
   entries too (each with its `state`), and `Host._transmitted_since`
   reports them as `transmitted` with `detail: "outcome unknown"`. Tests:
   `test_performed_since_lists_a_send_whose_outcome_is_unknown`,
   `test_a_rollback_lists_a_send_whose_outcome_is_unknown`.
8. [x] **After an old-state restore, the record has no `idempotency_key`**
   (low). Real: reproduced in the extended test. `fill_idempotency_key`
   also sets the key on the pass's record when the state still holds it
   (`cur.record >= records_base`). `core/tests/effects.rs::idempotency_key_filled_on_v1_restore`
   strips the records' keys and checks the record after the restored
   attempt succeeds.
9. [x] **`WorkflowRunner(destinations=[...patterns])` split into
   characters** (low). Real. `WorkflowRunner.start` checks the shape first
   (`_destination_policies`): a string, or a policy that is a string or
   holds a non-string, raises `TypeError` ("each policy is a list of
   patterns"). Test: `test_a_flat_list_of_patterns_is_a_type_error`.
