## Stages (one commit each, validated before commit)

Re-planned after D-lang (Rust core): the validator and executor move into
`core/`; the contract is `tasks/design-114.md`.

- [x] S1 Rust core crate, hardened YAML 1.2 loader (saphyr), maturin
      packaging, PyYAML parity test, CI job.
- [x] S2 Validator ported to the core (inference, `$ref`, consumer checks, L4
      patches) with the error-code fixes; CLI is a thin wrapper; differential
      against the Python validator over every fixture and catalog.
- [x] S3 Expression grammar B (CEL-compatible), gate `phase`, L3 expression
      checks, conformance fixtures, cel-go differential in CI.
- [x] S4 Edge + flag semantics: `precedes` ordering-only (V102), `conflicts_with`
      concurrency (F504), `soft_requires` any-of presence (W601) with the
      re-oriented edges, flag inheritance + downgrade warnings (W602),
      `mutation_overridable`, unknown fields (W604), spec version (W605/V109);
      catalog/fixture data fixes; JSON schema relaxed to §5; new conformance
      fixtures and warning assertions; `WorkflowEngine` façade over the core
      (`_core.Validator`); checkpoint reservation race fix; vendored catalogs
      regenerated by `sync_skill_schemas.py` with a `--check` drift gate.
- [ ] S5 Extensions E1–E6 static validation (durations, cron/tz, triggers,
      recovery/handlers, wait, approval, delegation, quorum,
      `workflow_extensions.requires`/V106).
- [ ] S6 Sans-IO executor in the core + Python driver + runtime fixtures.
- [ ] S7 RFC-0003, STANDARD v1.1.0, EDGE_TYPES errata, docs, changelogs;
      Q3 issue + #114 reply drafts (not posted).
